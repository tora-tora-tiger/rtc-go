# 詳細ログ追加の実装ログ

## 実行日時
2025年12月12日 15:55

## 目的
通信状況の詳細把握のため、ScreenShare.tsxに大量のconsole.logを追加

## 追加されたログ

### 1. ボタンクリック関連
- ビデオ通話開始ボタンクリックの記録
- Socket接続状態とIDの表示
- メディアデバイスアクセスの開始と成功
- トラック詳細（種別、ラベル、状態）

### 2. WebRTCシグナリング関連
#### Offer送信時
- WebRTC Offer生成開始
- PeerConnection状態（connectionState, iceConnectionState）
- Offer生成成功（タイプ、SDP先頭50文字）
- LocalDescription設定完了
- ICE収集状態
- Socket送信前後の状態確認

#### Answer受信時
- Answer受信記録（タイプ、SDP先頭50文字）
- RemoteDescription設定処理
- PeerConnection状態の変化

#### ICE Candidate関連
- ICE Candidate受信と送信
- Candidate詳細（IP、ポート、プロトコル、タイプ）
- ICE収集完了の記録

### 3. Socket.io接続関連
#### 接続プロセス
- 接続開始の記録
- サーバーURLと接続前状態
- socket.connect()呼び出し

#### イベントハンドラ
- `connect`: 接続確立時の詳細情報
- `disconnect`: 切断理由と状態
- `connect_error`: エラー詳細
- `offer`: 受信からAnswer送信までの全プロセス
- `answer`: 受信とRemoteDescription設定
- `ice`: 受信と追加処理

### 4. メディアトラック処理
#### トラック受信
- トラック種別、ID、ラベル、状態
- 映像・音声トラックの処理開始

#### 映像処理
- 映像要素の作成と設定
- 再生開始とDOM追加
- 要素数のカウント
- 再生エラーの記録

#### 音声処理
- 音声要素の作成と再生
- DOMへの追加

### 5. エラーハンドリング
- メディアデバイスアクセスエラー
- Socket.io接続エラー
- WebRTC処理エラー
- 各エラーの詳細情報（メッセージ、種類）

### 6. クリーンアップ処理
- コンポーネントアンマウント時の処理
- Socket切断
- メディアトラックの停止
- トラック数と停止状況の記録

## ログの絵文字表記

| 絵文字 | 意味 | 使用箇所 |
|--------|------|----------|
| 🟢 | ボタンクリック/開始 | ユーザーアクション |
| 📍 | 状態情報 | 接続状態、IDなど |
| ✅ | 成功 | 処理成功時 |
| ❌ | エラー | エラー発生時 |
| 📹 | メディア/映像 | カメラ、映像処理 |
| 🔊 | 音声 | マイク、音声処理 |
| 🔗 | 接続/追加 | WebRTCトラック追加 |
| 🤝 | ハンドシェイク | Offer/Answer交換 |
| 📡 | 送信/受信 | Socketメッセージ |
| 🧊 | ICE | ICE Candidate処理 |
| 🎬 | 映像/動画 | 映像トラック処理 |
| 🧹 | クリーンアップ | コンポーネント終了 |
| 🛑 | 停止 | トラック停止 |

## デバッグ効果

### 1. 通信フローの可視化
- Socket.io接続確立のタイミング
- Offer/Answer交換のプロセス
- ICE Candidateの交換状況

### 2. WebRTC状態の監視
- PeerConnectionの状態遷移
- ICE接続状況
- メディアトラックの追加と受信

### 3. エラー特定
- 各処理ステップでのエラー発生箇所
- エラーの詳細な原因
- Socket接続問題の特定

### 4. パフォーマンス監視
- メディアデバイス取得時間
- WebRTC処理時間
- 映像再生の成功率

## 使用方法

1. **ブラウザコンソールを開く** (F12 → Consoleタブ)
2. **ビデオ通話を開始ボタンをクリック**
3. **ログを観察**:
   - 接続プロセスの正常性
   - Offer/Answer交換
   - ICE Candidateの交換
   - トラックの受信と再生

## 期待されるログフロー

### 正常時
1. `🔌 Socket.io接続を開始します`
2. `✅ Socket.io接続が確立されました`
3. `🟢 ビデオ通話開始ボタンがクリックされました`
4. `📹 メディアデバイスへのアクセスを開始します`
5. `✅ メディアデバイスの取得成功`
6. `🤝 WebRTC Offerの生成を開始します`
7. `📡 Offerを送信します`
8. （相手側が受信）`📥 Offerを受信しました`
9. （相手側が応答）`📡 Answerを送信します`
10. （受信）`📥 Answerを受信しました`
11. `🧊 ICE Candidateイベントが発生しました`
12. `🎬 トラックを受信しました`

### 異常時
- 各ステップで❌エラーログが出力
- 接続状態やエラー詳細が記録

## 結果
これにより通信のどの段階で問題が発生しているかを正確に特定でき、デバッグが大幅に容易になりました。
